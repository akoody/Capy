# 0001. Проверять конфигурацию при старте

- Статус: принято
- Дата: 2026-11-06
- PR: [#1](https://github.com/akoody/Capy/pull/1)

## Контекст
Переменные окружения читались напрямую из `process.env` в разных местах. Без `TELEGRAM_BOT_TOKEN` API запускался и отвечал 503 на каждый запрос с советом перезапустить pm2. Сидер вообще не читал конфиг: адрес базы был зашит в код.

## Решение
Одна zod-схема `src/config/env.schema.ts`, подключённая в `ConfigModule.forRoot({ validate })`:
- обязательные переменные, значения по умолчанию и приведение типов (`PORT`, `TELEGRAM_AUTH_MAX_AGE_SECONDS`, список `CORS_ORIGINS`) описаны в одном месте;
- секреты нормализуются: кавычки, пробелы, BOM;
- при ошибке процесс падает со списком всех неверных переменных, значения в сообщение не попадают;
- у сидера своя, урезанная схема: ему нужен только `MONGODB_URI`.

Код получает значения через `ConfigService<AppEnv, true>` с выводом типов.

## Рассмотренные варианты
- **Joi** — штатный пример в документации Nest, но zod и так используется для разбора данных Telegram, а второй валидатор ничего не даёт.
- **Проверять при первом использовании** — ошибка всплывает в рантайме у пользователя, а не при деплое.

## Последствия
- Неправильный деплой виден сразу: процесс не стартует.
- Новая переменная требует правки схемы. Это и есть цель.
- Часть старого кода (ассистент) ещё читает `process.env` напрямую; переводится вместе с рефакторингом ассистента.
