# 0007. Фоновые задачи в отдельном процессе без очереди

- Статус: принято
- Дата: 2026-11-09

## Контекст
Напоминания отправлял cron внутри процесса API: второй экземпляр API продублировал бы все сообщения. Сбой Telegram при этом не учитывался, и напоминание помечалось отправленным, то есть терялось. Изначальный план предполагал BullMQ и Redis.

## Решение
- Отдельная точка входа `src/worker.ts` с `WorkerModule`. API больше не содержит cron и масштабируется независимо.
- Перед отправкой напоминание атомарно занимается условным `updateOne` по `$elemMatch`, поэтому каждое обрабатывает один экземпляр.
- Занятое упавшим воркером освобождается через 5 минут. Неудачная отправка повторяется, после 5 попыток напоминание помечается `failedAt`.

## Рассмотренные варианты
- **BullMQ + Redis** — ретраи, отложенные задачи и панель из коробки, но это новый компонент инфраструктуры ради одной задачи раз в минуту. Источник истины всё равно остаётся в задаче в MongoDB, очередь пришлось бы с ней синхронизировать при изменении и отмене напоминаний.
- **Cron с распределённой блокировкой** — один экземпляр работает, остальные простаивают; поштучный захват проще и позволяет работать параллельно.

## Последствия
- Доставка «хотя бы один раз»: при падении между отправкой и записью напоминание придёт повторно через 5 минут.
- Точность определяется интервалом опроса (минута), чего достаточно для напоминаний.
- Появятся задачи с большой нагрузкой, например AI-разборы в фоне, — решение стоит пересмотреть в пользу очереди.
