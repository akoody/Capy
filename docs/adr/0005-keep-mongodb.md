# 0005. Остаться на MongoDB

- Статус: принято
- Дата: 2026-11-07

## Контекст
Финансовые данные — естественный кандидат на реляционную базу: транзакции, балансы, отчёты с агрегатами. При этом проект уже работает на MongoDB с данными пользователей, а модель документов (пользователь, его цели, задачи, заметки) ложится на неё без натяжек.

Текущие проблемы с деньгами не связаны с выбором базы:
- суммы хранятся во float без валюты;
- операции над несколькими документами (транзакция + кошелёк) не атомарны;
- нехватка средств при списании возвращает пустой ответ вместо ошибки.

## Решение
Остаёмся на MongoDB и чиним модель денег:
- суммы хранятся целыми в минорных единицах вместе с кодом валюты;
- операции над несколькими документами идут в транзакциях MongoDB (нужен replica set, в том числе для локальной разработки и CI);
- одиночные изменения баланса — атомарный `$inc` с условием (уже сделано в [#3](https://github.com/akoody/Capy/pull/3));
- миграция существующих данных — отдельным скриптом с проверкой сумм до и после.

## Рассмотренные варианты
- **PostgreSQL** — честные транзакции, внешние ключи, `numeric` для денег. Но это переписывание всего слоя данных и миграция живых данных, что примерно удваивает объём работ без новой ценности для пользователя.
- **Decimal128 вместо минорных единиц** — точное хранение, но неудобная арифметика в JS и сериализация в JSON; целые числа проще и надёжнее.

## Последствия
- Нужен replica set везде, где используются транзакции.
- Решение пересматриваем, если появятся сложные отчёты с соединениями или требования аудита, для которых MongoDB неудобна.
