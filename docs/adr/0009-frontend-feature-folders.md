# 0009. Экраны по фичам, без монорепозитория

- Статус: принято
- Дата: 2026-11-09

## Контекст
Экраны фронтенда разрослись до 400-700 строк: запросы, вычисления, форма и разметка лежали в одном файле, тестов не было. Изначальный план предполагал pnpm workspaces, `apps/*` и общий пакет контрактов.

## Решение
- Крупные экраны лежат в `frontend/src/features/<фича>`: экран собирает данные, компоненты отвечают за разметку, вычисления вынесены в чистые модули с unit-тестами.
- Экраны целиком проверяются тестами на vitest и Testing Library с подменой API.
- API и фронтенд остаются двумя npm-проектами в одном репозитории. Типы ответов фронтенд описывает сам в `types.ts`.

## Рассмотренные варианты
- **Монорепозиторий с общим пакетом**: переносит все пути, CI и деплой, но кода для переиспользования почти нет: бэкенд хранит копейки и Mongoose-документы, фронтенду нужны готовые суммы и JSON.
- **Типы из OpenAPI**: схема описывает запросы, но контроллеры не аннотируют ответы, а именно они расходятся на практике. Сгенерированные типы создали бы ложную уверенность.

## Последствия
- Изменение формата ответа API нужно вручную отразить в `types.ts`; TypeScript этого не заметит.
- Когда появится второй клиент или ответы будут описаны DTO, стоит генерировать типы из `/docs-json`.
- Экраны меньшего размера пока лежат в `views/`, а `AddTransactionModal` остаётся единым файлом. Их переносят по мере изменений.
